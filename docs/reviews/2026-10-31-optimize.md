## 1. P0：先说"不出事"

### 1.1 配置改成"整份替换"

- **问题**：`Config::Save` 用 `_wfopen(path, L"wb")` 直接打开正式文件，截断后就地写。
  写到一半断电 / 崩溃，`config.ini` 只剩半截，刷新间隔、阈值、别名、面板位置全部回默认。
- **做法**：写 `config.ini.tmp` → `fflush` → `MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH)`；
  目标被短暂占用时退让 50ms 重试一次，仍失败则保留 `.tmp`，正式文件不动。
- **配套**：新增 `schema=1` 键；`Load()` 末尾的兼容处理抽成 `MigrateConfig(c, fromSchema)`，
  迁移改了值才回写一次。
- **验证**：改动后运行过一次，`config.ini` 变成 9 行（多出 `schema=1`），
  `interval=300 / low_threshold=20 / panel_x=1960 / panel_y=1250 / autostart=1` 全部保留。

### 1.2 `--selftest`：把 14 条断言搬回仓库

- **问题**：`2026-10-29-fixes.md` 里 C1/C2/C8/C12 的验证程序是 `/tmp/verify/v.cpp`，
  临时目录早已被清理。于是同一段解析逻辑"改没改坏"只能靠真机和记忆回答。
- **做法**：
  - 新增 `src/decode.h`，把 `ExtractBits` / `NormalizeLevel` / `DecodeBatteryReport`
    移出匿名命名空间（定义仍在 `providers.cpp`，只是有了外部链接）。
  - 新增 `src/selftest.cpp`：22 条断言，覆盖 C1（reportId=0 偏移）、C2（0..1 归一化）、
    C8（多子字段）、C12（负偏移 / 超宽位宽 / 越界）。
  - `yudian.exe --selftest [文件]` 输出 TAP 文本 + 同目录 `.rc` 标记文件；全过退出码 0。
  - 自检在读配置**之前**结束，不碰 `%APPDATA%`。
- **验证**：22/22 通过，见 `build/selftest.txt`。

### 1.3 `build.bat` 接门禁

- **做法**：`[3/4] self test`，用 `start /wait` 跑（cmd 不等 GUI 子系统的程序）；
  判据用 `.rc` 文件而不是退出码，避免"没跑也算通过"。
- **失败时的处置**：打印 TAP、把新 exe 改名成 `build/yudian.broken.exe`、`exit /b 1`。
  不留一个"能双击但已经坏掉"的程序。
- **验证（故障注入）**：把 `NormalizeLevel(55,0,100) == 55` 临时改成 `== 56` →
  构建输出 `# 22 checks, 1 failed` + `[ERROR] self test failed`，`build.bat` 退出码 1。
  断言已还原。

### 1.4 诊断汇总行

`--list` 报告的开头现在是两行：

```
汇总: 1 台 · 可读 1 · 无读数 0（未应答 0 / 占用 0 / 报文异常 0 / 不支持 0） · 枚举 63ms
分项: 罗技 1 台/1047ms · 索尼 0 台/0ms · 厂商接收器 0 台/0ms · ATK 0 台/0ms · ...
```

原来是一行手写 `swprintf` 把 t1..t4 拼起来——加一条链路就漏统计。现在每个链路的耗时和产出条数
由扫描循环自己累计，加链路自动进统计。

## 2. P1：让"加设备"变成加一行

### 2.1 认领表取代手工排除

- **问题**：`ScanGeneric` 开头有 6 行 `continue`，把其它链路的匹配条件抄了一遍；
  `ScanCompx` 里还有一句单独的 `IsNordic54` 排除。任何一条链路的判定改了，这里不会跟着变。
- **做法**：扫描前先建 `owner` 表：按 `kProviders` 顺序，对每台接口问 `claims()`，先到先得。
  通用兜底只处理 `owner` 里没有的接口。
- **验证**：用改动前的源码另编一份 `baseline.exe`，两边各跑 `--list`，
  设备行**逐字节一致**（本机罗技 G304，20%）。

### 2.2 链路表 + 统一签名

```cpp
struct ScanCtx { const std::vector<HidInfo>* all;
                 const std::map<std::wstring, const ProviderDesc*>* owner;
                 bool fullSweep; };
struct ProviderDesc { id; label; claims; hidEnum; scan(ScanCtx&, out); };
const ProviderDesc kProviders[] = { ... 8 条 ... };
```

- `MonitorScan` 从"手写调用链 + 4 段计时"退化成 30 行循环。
- 各 `ScanXxx` 签名统一成 `(const ScanCtx&, std::vector<Reading>*)`；
  罗技的两条函数（HID++ / 无 HID++ 说明行）合成一个入口，BLE 用一个适配器。
- 退出检查（`ScanCancelRequested`）从 4 处显式 `return` 变成循环里一处 `break`，语义不变。

### 2.3 `Outcome` 枚举

`Reading` 新增 `Outcome { Ok, NoReply, Busy, BadFrame, Unsupported }`，
在罗技 / 索尼 / Compx / Nordic / 迈从 / 飞智 的失败分支上标注。

**注意：只加不改**——界面仍然用 `status` / `detail` 的中文文案，`Outcome` 目前只用于汇总统计。
把文案全部改成"枚举 + 一处渲染"是下一步的事，会牵动 `ui.cpp` 的排版，不放在这一轮。

### 2.4 描述符解析的源头校验

`ParseDescriptor` 里补三处：

- 位宽不在 `1..32` 的字段**不产出**（原来只在 `ExtractBits` 兜底）。
- 展开子字段时 `itemStart + k*fieldBits` 用 `long long` 算，超过 `INT_MAX` 就停。
- 偏移累加同样用 `long long` 再夹住——畸形描述符里 span 被钳到 1GB 位，连续几项仍可能把 int 加成负数。

## 4. 有意不做 / 遗留

1. **N17（通用 HID 用 `HidP_GetValueCaps` 重写）**：未做。
   这一轮把"解析层"的断言补齐了，但 `HidP_*` 那条路径需要真实设备的 value caps 数据才能验证，
   本机没有"按标准 HID 上报电量"的设备。按清单里定的顺序：**先有夹具，再改实现**。
2. **`Outcome` 只标注了失败分支**：成功路径全是默认 `Ok`，够用于统计；
   彻底的"枚举替代字符串"没做（会动 `ui.cpp` 文案）。
3. **BLE 链路没有 `Outcome`**：它读不到就不产出记录（设计如此），没有"失败行"可标。
