## 关于 reviews/

这些是「检查代码发现了什么问题、怎么修的」的原始记录，按发生时间排序：

| 文件 | 内容 |
|---|---|
| `2026-10-29-handoff.md` | 第一次审查交接：列出 15 个高危问题（C1–C15）与 Python 侧问题 |
| `2026-10-29-round2.md` | 第二次审查：逐条复核，并补完 50 个 Python 脚本的审查 |
| `2026-10-29-fixes.md` | 修复记录：每一项怎么改、怎么验证、哪些没能验证 |
| `2026-10-31-optimize.md` | 按 Oink 借鉴清单做的第一轮优化：配置原子写、自检门禁、链路表、解析层防护 |

**平时不用读**，它们更像病历而不是说明书。只有在下面两种情况才需要翻：

- 想改某段代码，但不确定当初为什么写成这样 → 搜关键词，看有没有踩过坑；
- 想确认某个问题到底修没修 → `fixes.md` 里有逐条状态表。

## 写文档的约定

- 一份文档只讲一件事，标题写清楚，别做成大杂烩。
- 开头用一两句话说明「这份是什么、什么时候该看」，读者不用读完才知道要不要读。
- 目录结构只在根目录 `README.md` 维护，这里不重复。
- 历史文档不删改内容，只在开头加一句说明（比如路径变了），保留当时的原貌。
