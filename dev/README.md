# 开发工具 · 说明

这里是做「余电」时用过的辅助工具，**不属于产品**：不参与打包、不随程序分发，删掉也不影响
`app/build/yudian.exe` 运行。留着只是为了「当初为什么这么做」有据可查。

| 目录 | 是什么 | 大概什么时候会用到 |
|---|---|---|
| `probes/` | 48 个 Python 小脚本，用来试探各品牌设备的电量协议 | 想加一款新设备、想查某个旧结论怎么来的 |
| `ui-labs/` | 4 个独立的界面实验程序（C++） | 想重做图标、想调面板的滚动与提示窗位置 |

## probes/ —— 协议探针

程序要读一只没人公开协议的鼠标电量，得先知道「发什么、收什么、第几个字节是电量」。
这些小脚本就是干这个的：发一帧试探报文，看有没有回包。

跑法（需要装 Python 3，在本目录下执行）：

```bat
python hidprobe.py enum                      :: 列出电脑上所有 HID 设备
python probe3.py 046D:C53F FF00:0002 20 00   :: 给指定设备发一帧，看回包
python caps.py 046D:C53F                     :: 看这台设备上报了哪些数值、范围多少
```

每个脚本对应一次具体的「这条路走不走得通」的提问，**完整清单和结论在那个目录的 README 里**，
不用逐个点开看。

## ui-labs/ —— 界面实验

四个自成一体的单文件程序，各自带一份渲染代码，编出来双击就能看效果：

| 文件 | 用来做什么 |
|---|---|
| `iconnum.cpp` | 图标方案对比（数字型：把电量直接写成数字） |
| `iconlab.cpp` | 图标方案对比（图形型：用电池形状表示） |
| `panel_test.cpp` | 面板滚动与点击命中测试（需要主程序在跑） |
| `toast_test.cpp` | 提示窗位置、尺寸、是否抢焦点（需要主程序在跑） |

编译其中一个（在 `dev/ui-labs/` 下）：

```bat
g++ -std=c++17 -O2 -municode -DUNICODE -D_UNICODE iconnum.cpp -o iconnum.exe ^
    -lgdiplus -lgdi32 -luser32 -lole32 -luuid
```

图标类程序运行后会直接输出一张对比图；面板/提示窗类程序需要先把 `app/build/yudian.exe` 跑起来。

## 一句话原则

这些工具的价值在**过程**，不在代码本身——它们记录了哪些路走不通。真要清理，建议先看一眼
`probes/README.md` 里的结论表，确认不再需要再删。
