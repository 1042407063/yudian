# 2026-10-27

## 余电：深色模式提示卡 + 图标重做 + 架构审查

### 深色模式「扎眼」的两个真因

1. **主题只在启动时解析一次**。`g_colors` 在 `UiCreate()` 里赋值，`UiRebuildTheme()` 是死代码（没有任何调用点），主窗口也没处理 `WM_SETTINGCHANGE`。托盘程序常驻数天，中途切成深色后，提示卡仍是一张纯白卡片 —— 这才是「扎眼」的主因。
2. **两套主题来源打架**。卡片底色用 `g_colors`，而左侧图标却调 `IsDarkTheme()` 重新读注册表。两者不一致时，深色卡上会画出一整块近白方块（`#F5F5F7`）、或干脆整块消失（`#1D1D1F` 叠在 `#1C1C1E` 上）。

修法：`g_dark` + `g_colors` 由 `SetThemePalette()` / `RefreshTheme()` 唯一写入，所有绘制只读 `g_dark`；`IsDarkTheme()` 退化为「只做解析」；主窗口加 `WM_SETTINGCHANGE`（`ImmersiveColorSet`）→ `UiRebuildTheme()`；弹出提示卡前再 `RefreshTheme()` 一次。

### 提示卡视觉

- 卡片深色用 `g_colors.tile`（`#2C2C2E`）而不是窗口底色 `#1C1C1E`：纯黑贴在深色壁纸上像挖了个洞。
- `ApplyPanelCorners` 加 `DWMWA_USE_IMMERSIVE_DARK_MODE`（20，回退 19），否则深色卡片外面有一圈亮色 DWM 边框。
- 左侧图标从「墨块 + 橙色 20」改成**程序图标本身**（`ChipStyle::App`，恒定墨底白闪电）。数字不进图标：36px 方块塞两位数不清楚，且与正文重复。
- 百分比改到正文里单独染色加粗（`DrawTextRuns`）。**测量与绘制必须共用 `StringFormat::GenericTypographic()`**，默认格式带内边距，逐段拼接会裂出可见的缝；「剩余」后的空格会被排版吃掉，要用 `\u00A0`。

### 架构审查（已修）

| 问题 | 性质 |
|---|---|
| `wchar_t buf[160]` 却 `swprintf(buf, 192, ...)` | 缓冲区边界与实际容量不符，改 `_countof` |
| `g_quit` / `g_intervalSec` / `g_forceScan` 用 `volatile` | C++ 上不建立 happens-before，data race，换 `std::atomic`（均为字长内无锁实现） |
| 厂商扫描按 path 去重 | 同一设备两个集合会出两行，改按 VID:PID 合并 |
| 通用兜底不排除厂商 VID/PID | 与厂商链路重复上报，加 `FindVendor` 跳过 |
| `MakeTrayIcon(level, charging, size)` 参数已废弃 | `UpdateTrayIcon` 里还在算最低电量（死逻辑），简化签名并删掉 |

**没动**：`HidDevice::Read` 把「设备错误」和「超时」都返回 0，误判为无回复；改动影响所有读取路径，无真机数据前不动。`providers.cpp` 995 行 / `ui.cpp` 1684 行的拆分同理——纯文件搬运，零行为收益，风险大于收益。

### 验证

- 深色真机：config `theme=dark` 启动，`tools/toast_test.cpp` 从运行中的进程抓到 576×120 卡片，底色 `#2C2C2E`、图标墨底白闪电、20% 橙色，无白边。
- `WM_SETTINGCHANGE` 冒烟：`tools/theme_test.cpp` 发送后主窗口存活、面板仍可见。
- 从零 `rm -rf build` 构建通过，exe 535,040 字节，子系统 `2 (GUI)`。
- G304 仍 20%；稳态扫描 265–375 ms（设备休眠程度不同，波动正常）；多帧绘制唯一哈希 = 1。
- 空闲内存 23.8 MB，12 秒后 23.9 MB，无增长。

### 再改：图标统一墨底，不再按任务栏反色

用户反馈「深色模式图标是白的，提示卡是黑的，不统一」。确实是我上一轮的错误取舍：**同一个图标在不同主题下换一套颜色，比它在某种底色上略不显眼更糟**。

- `DrawChipGlyph` 收成一套：恒定 `#1D1D1F` 底 + 白闪电，与 exe 图标完全一致。
- 深色下补一圈 25% 白描边（`C(0xFFFFFF, 66)`，宽 `max(1.0f, 0.8*s)`）。第一版用 `#4A4A4C` 实色，16px 下几乎看不见；白色半透明在任意深色任务栏上都成立。
- 顺带删掉因此变成死代码的整套「数字图标」渲染：`LevelColor`、`struct Glyph`、`RenderGlyph`、`DrawNumber`、`ChipStyle` 枚举，以及 `g_toastCharging` 和 `UiShowToast` 的 `charging` 参数。exe 从 535,040 → 531,968 字节。
- 验证：16/24px 在 `#202020` 底上放大 8 倍看，描边连续、闪电清晰；真机深色提示卡图标与卡片同为墨色系。

**教训**：反色（invert）看起来是“适配”，实际是制造第二套视觉。跨主题保持一致性的正确做法是**同一形态 + 一像素级的边界补偿**，不是换配色。

## 余电：面板防呆 + VGN 电量适配

用户三条反馈：面板不在右下角、没有关闭/退出按钮、VGN 蜻蜓读不出电量。

### 面板位置

旧代码 `x = cursor.x - PanelWidth()/2`（按光标居中），面板会飘在屏幕中间偏下。改为 `PlacePanel()` 统一锚定工作区右下角，留 `S(8)`；`WM_DPICHANGED` 不再用系统的建议矩形（会把锚点带走），按右下角重算；列表行数变化时也从右下角往上长。

### 防呆

- 标题栏 `↻` 右侧加 `×`（只收面板，不退程序）；页脚加「退出」，**两次确认**：第一次变红色「确认」+ 红色提示，4 秒超时 / 点别处 / 失焦都撤销。
- 面板右键出菜单；菜单文案随状态变（收起 / 打开）。
- 菜单弹出期间 `g_menuOpen` 阻止 `WM_ACTIVATE` 失焦隐藏，否则「收起面板」会变成重新打开。
- 交互测试（DPI-aware，150%）：面板 600×638 物理像素，距工作区右/下各 12px；× 收起、退出两次确认、撤销都通过。

### VGN / Compx 协议

参考 `k0te1ch/powerpeek`（社区逆向，VGN 蜻蜓 F1 MOBA 实机验证）。旧实现的四个问题：

1. **集合选错**：按 VID/PID 取第一个 `0xFF02/0x0002`，可能拿到 8 字节鼠标集合，写 17 字节必失败。现在按 `inputLen/outputLen >= 17` 筛，同接收器多集合逐个试，稳态缓存可用集合。
2. **只认 PID 表**：新 PID 直接跳过。现在 VID ∈ {3554,373B,260D,33E4} 或产品名带 VGN/VXE/ATK/Pulsar 就按同族试。
3. **不校验回包**：帧尾 `0x55 - sum(前16字节)`，请求回复都校验；再判状态字节、长度、`0%+0mV`（= 接收器后面没鼠标）。
4. **只读一次 250ms**：接收器约 1/30 丢包，改 3 次重发 × 120ms（实测回包 1~23ms）。

型号用 `0x10` 命令让鼠标自报 customer/model（`2:6` = F1 MOBA），VGN F1 全系共用接收器 PID，靠 PID 分不出来。新增 `--vendor <文件>` 输出原始帧，`--list` 也附上这段诊断。

顺带：罗技冷启动偶尔漏设备（probe 100ms 不够），全量扫描改用 250ms，5 次冷启动 5 次都读到。

### 数据

- exe 530,432 字节；150% DPI 下面板 600×638。
- 本机无 VGN 硬件，Compx 解析按参考实现的实测帧核对过（`08 04 ... 1e 00 0e 95 ... 86` = 30% / 3733mV；`08 10 ... 02 06 ... e5` = 2:6），**仍需真机验证**。
- 预览图全部用 `--shot` 重生成；新增 `armed` / `multi` 两个仅截图用的预览模式。

## 余电：刷新间隔从 30 秒改为默认 2 分钟

用户实测 VGN 蜻蜓已能读电量，反馈 30 秒太频繁。确认结论：鼠标满电 50~100 小时，掉 1% 要 30~60 分钟，30 秒轮询没有信息增益。

- 档位统一到 `app.h` 的 `kIntervals = {60,120,300,600,1800}`（1/2/5/10/30 分钟），默认 120 秒；菜单与 `WM_COMMAND` 共用这一份，删掉两处各自硬编码的数组。
- `Config::Load` 做归一：`<60` 秒只可能来自旧版（旧默认 30），按 120 处理；其它非档位值吸到最近档位，否则菜单里一个都不勾。
- 旧配置 `interval=30` 已验证渲染为「2 分钟自动刷新」（用临时 APPDATA 跑 `--shot`，不碰用户真实配置）。
- README 新增「轮询频率与耗电」：设备侧一次往返 1~23ms（含 USB 调度），2 分钟档射频占空比约 0.002%；设备睡着重来不应答，查询不会叫醒它；电脑侧 125ms/次 ≈ 0.1% 单核、23.7MB 常驻。

替换 exe 时用户正在运行旧实例（PID 24600），已关闭后重建，需提醒重新启动。

## 余电：面板可拖动 + 视觉重做（分层窗口）

用户要两件事：面板能拖走（躲输入法工具条）、整体更精致（配色/间距/圆角/阴影/动效），默认位置与功能不变。

### 拖动

- 标题栏空白处按下 = 拖动把手（按钮排除），`SetCapture` + 3px 阈值区分点击与拖动；拖动只 `SetWindowPos`，不重绘。
- 边界：按**卡片矩形**夹进光标所在显示器的工作区（不是窗口矩形，窗口比卡片大一圈阴影余量）。
- 位置存 `panel_x`/`panel_y`（卡片左上角，物理像素）；中心点不在任何显示器上就判失效回默认；右键菜单加「面板回到右下角」。
- 实测：拖到 (150,120) 落在 (151,121)；拖到屏幕外停在 (0,0)；复位回右下角 (1948,854)@150%；重启后位置 (400,300) 仍在。

### 分层窗口

- `WS_EX_LAYERED` + `UpdateLayeredWindow`，窗口 = 卡片 + 四周 36px 阴影余量；`WM_NCHITTEST` 在卡片外返回 `HTTRANSPARENT`，且所有鼠标坐标先减 `ShadowPx()`。
- 阴影：卡片圆角矩形 → 3 次盒式模糊（半径 2 紧收 + 半径 8 散开两层叠加），按尺寸+主题缓存；直通 alpha 画布逐像素预乘（64KB 查表，全不透明走 memcpy）。
- 文字改 `TextRenderingHintAntiAliasGridFit`（ClearType 在 alpha 画布上会渗色）。
- 动效：打开淡入 + 上浮 10px（卡片在画布内位移，阴影不动）；悬停/开关滑块 16ms 定时器插值；出现动画前 55% 就把 alpha 拉满。

### 踩到的坑

1. `ShowWindow(SW_HIDE)` 自己会发 `WM_ACTIVATE(WA_INACTIVE)`，把它当"失焦时间"会让 × 关闭后的下一次托盘点击被 260ms 防抖吞掉 → 加 `g_hidingSelf`。
2. 上膛的「退出」在标题栏按下时不会撤销（标题栏走拖动分支，不进按钮分支）→ 在 `WM_LBUTTONDOWN` 统一处理：只要没点在「确认」上就撤销。
3. 拖动跨不同 DPI 显示器时 `WM_DPICHANGED` 会调 `PlacePanel` 把面板拽回记忆位置 → 拖动中跳过重排。
4. 阴影区（alpha>0）会吃点击，必须 `HTTRANSPARENT`，否则点"影子"也激活面板。

### 视觉

- 配色重调：文字 #141416、次要 #6F6F76、发丝线 #E6E6EB、卡片 1% 垂直渐变；圆角 13→16；PAD 16→18；头 64→68、行 62→64、页脚 46→48。
- 1px 线画在 `.5` 上（整数坐标会被摊成两条半透明线）；图标态、百分比、页脚布局沿用但重新对齐。
- exe 539,136 字节；150% 下面板窗口 708×770（卡片 600×662）。

### 验证

`wincheck`（拖动/夹取/复位）、`clickcheck`（×、退出两次确认与撤销）、`pose`（跨进程位置记忆）全部 PASS；真机截屏确认分层合成、阴影、文字无异常。

## 余电：M185（C542 接收器）为什么读不到电量

用户插了两个接收器，新接的罗技 M185 没出现在面板里。实机排查：

- `--dump`：第二个接收器是 `046D:C542 "Wireless Receiver"`，接口只有 `0001/0002`（鼠标，IN 7）和 `0001/0000`（FEAT 8），**没有 `FF00` 厂商集合**。
- 8 字节特性报表：按 report id 0~3 × 长度 8~16 穷举 `HidD_GetFeature`，全部失败（87/无效参数），没有可读通道。
- Solaar 兼容表原文：`046d:c542` 这一类 Nano 接收器"do not implement the HID++ protocol at all"，明确不支持。
- 结论：**硬件层面没有电量上报**，罗技官方软件也读不到；M185 只有底部低电量指示灯。不是程序漏扫。

处理：新增 `ScanLogitechNoHidpp()`，对这一代接收器固定输出一条 `罗技 Nano 接收器 / 硬件不支持读数` 的记录，让"没检测到"变成"检测到了但硬件不支持"；`--dump` 给 C542 加标签；README 支持表 / 已知限制 / 排查各补一条。

实测 `--list` 现在输出 2 台：G304 20% + 罗技 Nano 接收器（--，硬件不支持读数）。exe 540,160 字节。

## 余电：设备增删的过渡动画

用户先提"区分手动/自动刷新"，随后纠正：**判据是面板看不看得见，不是手动还是自动**。按后者实现。

### 行为

- 面板可见 → 任何一次扫描（2 分钟自动 / 手动点刷新）带来的增删都播动画。
- 面板收起 → 直接换列表，`SettleRows()` 把半截动画落到终态；打开即最终状态（另有打开动画）。
- 移除判定：休眠不算消失（各链路会给"设备休眠"记录）；手动刷新当轮剔除，自动轮询给 1 轮宽限（`MonitorState::limit = manual ? 1 : 2`），防蓝牙瞬断。

### 动画

- 行状态 `RowAnim { float p; bool leaving; }`，p 同时驱动行高与透明度；列表用 `g_display`（离场行多留 ~190ms），真实数据仍在 `g_devices`。
- **两段式**：先收离场行（190ms），收完再按新顺序插入新增行（190ms）。一起做会因 5 行上限把新行挤出可视区，进场动画等于没播。
- 进场内容前 65% 不画、末段淡入：行高裁剪会露出半截百分比，像排版坏了。
- 离场 alpha = p²（先快速淡出，避免残留被切掉的字）；分隔线跟着当前行高走。
- 面板高度逐帧重算（`PanelHeightNow`），`WM_TIMER` 里比对窗口高度并 `PlacePanel`，贴底的面板自然往上长。

### 踩坑

1. 面板收起期间直接替换过列表，那些行**没有动画条目**；标记离场时若只在"条目已存在"分支做，删行会直接跳没。要顺手建条目。
2. 验证时 BitBlt 抓不到面板——一个全屏的 UWP 通知层盖在上面；`PrintWindow(PW_RENDERFULLCONTENT)` 能拿到窗口自身内容，抓帧改用它。
3. 演示数据带 8% / 18% 会触发低电量提示，而提示卡会主动收起面板，导致"首次打开失败"的假象。

exe 560,640 字节；README 增加"设备增删只在看得见时播动画"小节 + 3 条协议笔记。
