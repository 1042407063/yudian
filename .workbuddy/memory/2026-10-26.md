# 2026-10-26

## 外设电量 PeripheralBattery（C++ / Win32）

用户要做 Windows 托盘常驻工具，显示罗技 / 迈从 / 飞智 / PS5 手柄电量，要求轻量、包小、依赖少。

**选型过程**：先用 Python + PySide6 做了可运行原型（协议验证通过），用户要求先比较选型。对比 C#/.NET Framework 4.8、C++/Win32、Rust、Go、Python、Tauri、Electron 后，用户选定 **C++ / Win32 原生**，只要 Win10/11。Python 原型归档到 `prototype-python/`。

**交付**：`peripheral-battery/`，单文件 exe 486,912 字节（476KB），空闲内存 13.6MB，冷启动 <200ms。

### 关键技术结论（复用价值高）

1. **罗技接收器（PID C53F）只在长报文集合（usage 0x0002）上响应 HID++ 2.0**，短报文集合（0x0001）对已配对通道直接超时。必须两个集合都试，长报文优先。
2. **HID++ 错误帧格式**：`[0x10, devIdx, 0x8F, 地址, 功能|swid, 错误码, 0]`，错误码在 **byte5** 不是 byte4。0x08 = 未知设备，0x01 = 无效子命令。
3. 接收器通道探测：`错误码 0x08` = 空通道；**超时 = 有设备但休眠**。可据此给休眠设备占位条目。
4. **【已修正，见下方第 11 条】特性 ID 按大端解析**：最初误判为「设备不暴露电量特性」，实际是字节序问题。用户确认设备是罗技 G304（AA 电池）。
5. `HidD_GetFeature` 的 buffer[0] 必须是 report ID，否则读到 0 号报告。
6. MinGW 头文件缺 `USAGE` 类型（需自己 typedef）且 `hidpi.h` 需先 include `<winternl.h>`；GDI+ 需 `<propidl.h>`（WIN32_LEAN_AND_MEAN 下不自动带）。
7. `Gdiplus::GraphicsPath` 拷贝构造是私有的，不能按值返回，必须用输出参数。
8. `windows.h` 的 `DrawText`/`RoundRect` 是宏，自定义同名函数会被替换。
9. **MinGW 的 ld.exe 无法处理含中文的工具链路径**（会报找不到 crt2u.o），工具链必须放纯 ASCII 路径。项目源码目录可以含中文。
10. MinGW 链接 GUI 程序会自动加 `default-manifest.o`，自带 manifest 会冲突报 "multiple non-default manifests"；改为运行时 `SetProcessDpiAwarenessContext`。
11. **【关键】罗技 Lightspeed 接收器（PID C53F）的特性 ID 要按大端发**：HID++ 2.0 规范是小端，但实测 `getFeature` 发 `00 10`（=0x1000）返回索引 0，发 `10 00` 才返回索引 5。用 `--raw` 原始帧转储才看出来。代码已做「先小端失败再大端」自适应并按设备缓存。
12. **同一接收器有两个 HID++ 集合**：`usage 0x0001` 短报文、`usage 0x0002` 长报文。G304 只在长报文集合上响应，短报文集合对已配对通道超时。
13. **设备名 0x0005 分片有两种实现**：返回分片数（≤8，参数为分片序号）或返回字节长度（>8，参数为字节偏移）。G304 是后者，长度 37 → 按偏移 0/16/32 取。
14. G304 实测结果：`G304 Lightspeed Wireless Gaming Mouse / 鼠标 / 20% / 2.4G 接收器 / 电量偏低`，协议链路完整跑通。

### 已修 bug

- **刷新间隔改了没反应**：`g_interval` 在 ui.cpp 和 main.cpp 里各自定义了一份，菜单设置只写 main.cpp 那份，ui.cpp 那份永远停在 30 → 勾选不变、面板文案不变。改为 `CurrentInterval()` 单一数据源，并在改完后 `SetEvent` 让扫描立即按新间隔跑。
  - 验证手法：写了个 20 行 C++ 小工具 `tools/click_test.cpp`，`FindWindowW("PeripheralBatteryMain")` + `PostMessage(WM_COMMAND, id)` 模拟点菜单，然后用 config.ini 是否被改写作为断言（30 → 60 通过）。
  - 教训：**同一个语义的量绝不能在两处各存一份**；界面显示值必须走同一个访问器。
- **鼠标划过面板时底部时间戳来回跳 1 秒**：绘制时用 `time(nullptr) - 距扫描经过秒数` 现算。`time()` 按整秒跳、经过时长按扫描时刻起算，两者相位不对齐，重绘时机不同就落到相邻两秒。
  - 修法：扫描结果到达时记录一次 `g_lastUpdate`，绘制只读不现算。
  - 验证手法：加 `--shot-seq <前缀> <帧数> <间隔ms>`，同进程连续重绘多帧，**md5 必须全部相同**。做了反向验证（临时把现算逻辑放回去）→ 4 帧 4 个不同哈希，证明测试有效。
  - 通用教训：**任何在 paint 里算"当前时间"的界面都会抖**，时间必须来自事件而非渲染。

### 代码审查（第二轮）

发现并修复：
1. **高：设备超过 5 台完全不可见**。绘制只画 `g_devices[0..4]`，没有 `WM_MOUSEWHEEL`，README 却写了"超出滚动"。补了滚轮 + 右侧滚动条 + 滚动时悬停命中偏移 + 列表变短时收敛偏移。
2. **中：面板高度变化时向下长，可能压住任务栏**。改为 resize 后按监视器 `rcWork` 夹住 Y。
3. **中：每帧新建 11 个 GDI+ Font**。改成按 (字号,字重) 缓存，DPI 变化时 `ClearFontCache()`。
4. **中：没有 `WM_DPICHANGED`**。补上（改 g_dpi、清字体缓存、按建议矩形重排、重应用圆角）。
5. **低：`TrackPopupMenu` 后缺 `WM_NULL`**，菜单可能不消失。
6. **低：Win10 圆角区域在尺寸变化后没重应用**。
7. **自查发现的自伤 bug**：`UiApplyDevices` 里无条件刷 `g_lastUpdate`，导致"改刷新间隔"这种纯重绘也会把更新时间改成当前时间。加 `newData` 参数区分。

验证手法：新增 `tools/panel_test.cpp`（DPI 感知）→ 打开面板 → 发 `WM_MOUSEWHEEL` → `PrintWindow` 存 BMP，实测滚 2 格后首行从 MX Master 3S 变成 DualSense，滚动条滑块到底。

排查经验：**测试工具自己必须 DPI 感知**，否则 `GetWindowRect` 拿到的是被 Windows 虚拟化后的尺寸（576 被报成 384），会误判成"DPI 处理有 bug"。

踩的坑：
1. **`windres` 处理中文要先 `#pragma code_page(65001)`**，否则 VERSIONINFO 里的中文变乱码。
2. **填充高度小时圆角会把它吃掉**：`radius` 必须 `min(1.4*s, h/2)`，否则 5% 电量直接看不见。

## 苹果风改版（图标 + 面板）

用户要求「苹果风、简约高级、电量用数字表示」。做成了圆角方块 + 实时数字，面板整体换成系统设置式的列表。

### 图标

- 6 个候选容器形态在 `tools/iconnum.cpp` 里，`--big` 出大图、默认出尺寸对照表。
- 最终采用 **圆角方块（squircle）+ 白色数字**，24 网格下 `0.7..23.3`、圆角 `6.8`。
- 低电量整块换警示色（iOS 徽章做法）：≤20% 橙、≤10% 红，数字反白。
- 静态 exe 图标不放数字（数字会显得像在报错），改用闪电。

### 数字渲染（关键）

**GDI 画字比 GDI+ 锐利得多**（有字体微调）。但 GDI 写进 32bpp ARGB 会把 alpha 记成 0，图会整块消失。
解法：先 GDI 画到**黑色 DIB**，取 `max(r,g,b)` 当 alpha 搬到 GDI+ 位图。
再用墨迹 bbox 做**等比自适应**（超容器就缩字号）并**按墨迹中心对齐**——按字体框居中会看起来偏上。

### 面板

- 配色换成苹果系统色：`#1D1D1F / #86868B / #E5E5EA / #007AFF / #34C759 / #FF9F0A / #FF3B30`，深色 `#1C1C1E / #38383A / #F5F5F7 / #98989D`。
- 去掉行内色块和整行彩色进度条，改成：左侧无底色图标 + 名称/副标题 + 右侧小电池胶囊 + 百分比。
- 分隔线从文字起始处（x=52）起，不贯穿图标区——iOS 表格做法。
- **只有 ≤20% 才上色**，其余单色。彩色电量条会立刻显得像仪表盘。
- 数字用 Segoe UI（比例接近 SF Pro），中文用微软雅黑；`GetFont(px, weight, family)` 第三参选字族。
- 开关 38×22，开=系统绿；圆角 13px；面板宽度 380→400（长设备名放不下）。

### 踩的坑

1. **文字区右界没让开电池胶囊**，长设备名压到胶囊底下——右界必须按 `pillX - 10` 算，不能按百分比列算。
2. **`DrawChipGlyph` 内部读 `IsDarkTheme()`**，导致深色预览行画出深色方块贴深色底、整块看不见。主题必须由调用方传入。

4. `UiWriteAppIcon` 定义落在匿名命名空间里，链接报未定义——命名空间外要包一层公开函数（第四次踩）。

### 后续修复：控制台窗口 + 托盘底色

**双击弹出空黑窗口** = exe 被编成了控制台子系统（PE Subsystem=3）。根因不是 build.bat，是我后来手动 `g++` 时漏掉 `-mwindows`，把 GUI 版本覆盖掉了。
- 检测：`objdump -p exe | findstr /B Subsystem` → `00000002 (Windows GUI)` 才对。
- 修复：`build.bat` 里显式加 `-Wl,--subsystem,windows`，并在链接后用 `objdump` 复核，不是 2 就直接失败退出。
- 验证：启动前后 `conhost.exe` 数量不变（19→19），确认没拉控制台。
- 教训：**手工编译必须走 build.bat**，否则构建产物会悄悄降级；这类问题不会报错，只会表现为"多了一个窗口"。

**托盘底色不再随电量变**：用户反馈整块变黄太吵，要求和应用图标统一。
- 改成底色恒为 ink（浅色任务栏近黑 / 深色近白），低电量只给数字染色：深底亮橙 `#FF9F0A` / 亮红 `#FF453A`，浅底深橙 `#C93400` / 深红 `#D70015`。
- 结论：**整块变色只适合纯图形图标，一旦容器里有内容，底色就该稳定**。

### 再改：托盘图标 = 程序图标，自绘低电量提示

用户明确要求托盘图标和 exe 图标完全一致（黑方块 + 闪电），**不要在托盘显示电量数字**。
- `MakeTrayIcon` 里恒调 `DrawChipGlyph(g, s, -1, true, dark)`，参数直接 `(void)` 掉。

- 预览工具改成输出 16/20/24/32/40/48 尺寸对照，而不是电量档位对照。

**系统气泡不能用**：`Shell_NotifyIcon` + `NIF_INFO` 在 Win10/11 会转成系统通知，黄色警告三角、灰色图标、系统字体全部由系统绘制，无法定制。
- 改成自绘卡片：`PeripheralBatteryToast` 窗口，WS_EX_TOOLWINDOW|TOPMOST|NOACTIVATE，`ShowWindow(SW_SHOWNOACTIVATE)` 不抢焦点。

### 性能与交互修复（用户反馈"刷新慢、没反馈"）

**扫描 2.8 s → 125 ms（稳态）**，路径：
1. 探测超时 220/400ms → 100/150ms（HID++ 正常往返是毫秒级）。
2. 记住上一轮能应答的报文集合与通道（`g_liveIdx` / `g_liveColl`），稳态只探 1 个通道。
3. 设备名一次读到就缓存（`nameOk`），不再每轮发 3 个分片请求。
4. 全量扫描（`g_forceScan`）每 8 轮或手动刷新时做一次，非首选集合只探 1 个通道。

**发现的真 bug：幻影设备**。任何静默通道都会生成一条"设备休眠"记录，超时一多就凭空多出 5 台设备。修复：只有**确认存在过**的通道（live 集合或已有名字缓存）静默才算休眠。

**刷新交互**：悬停/按压圆底、环形 spinner（270° 圆弧 + 淡轨道，别旋转文字字形）、页脚立刻显示"正在更新…"、扫描中忽略重复点击、10 秒兜底停转。

**面板打开的刷新策略**：数据 3 秒内新鲜就不扫，避免"更新时间"莫名跳动。

**低电量提示加关闭按钮**：右上角 ×，点击只收窗不开面板；其它区域点击仍开面板。

**教训**：给"没应答"下结论前先分清「没有设备」和「没来得及」。超时 ≠ 休眠。

### 国产外设协议接入（无真机，照公开协议实现）

用户回家实测：迈从、VGN 读不到。查 GitHub 后确认协议是公开的，直接接进来。

**三套协议**（`providers.cpp` 的 `ScanVendor`）：
1. **Compx / Nordic 52840** — VGN/ATK/VXE/Zaopin/Scyrox/达尔优/G-Wolves 共用同一颗芯片。
   17 字节报文：`08 04 00×13 49`（末字节是校验，全帧和 0x55），回包 byte6=电量、byte7=有线标志。
   型号表 13 款，加新型号 = 一行 VID/PID。
2. **Nordic 54L15**（ATK Zero）— 64 字节，`08 7D 72 02 00 01 07 01`，回包校验 byte1==0x72 && byte5==0x07，电量 byte7。
3. **MCHOSE / Realtek** — 推送式：设备每 ~2 秒发 `0x13`/`0x1D`，整帧 XOR 0xFF，电量在 byte5、有线标志 byte4。
   **只被动接收，不发 0x11 0xF9 的 nudge**（那是写命令）。推送式结果缓存 90 秒，避免每轮阻塞 2 秒。

协议出处：Fan4Metal/ATK_tray（models.py）、Fan4Metal/mouse_tray（chipset/nordic52.py、nordic54.py、realtek.py）、XAVIER0229/GearPower。

**新增 `--dump`**：导出全部 HID 接口（VID/PID、UsagePage、IN/OUT/FEAT 长度、识别到的协议）。排查新设备靠这个，比来回问快。

**踩坑**：MinGW 宽字符 `swprintf` 的 `%s` 指 `char*`，宽字符串必须 `%ls`——不然设备名只出首字母。这是第三次踩同一个坑。
