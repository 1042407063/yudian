# 2026-11-21

## 修复任务栏浮窗闪烁与狼蛛键盘电量读取

- 浮窗根因：此前把默认浮窗的 `Shell_TrayWnd` owner 清空，并在 100ms 定时器和 `WM_WINDOWPOSCHANGED` 中按遮挡反复 `SetWindowPos(HWND_TOPMOST)`，与 Explorer 抢 z 序。Win32 规则实际是 owned window 始终高于 owner。
- 修复：`app/src/ui.cpp` 默认浮窗恢复以任务栏为 owner，拖出后仍清空 owner 独立置顶；删除遮挡比例检测及两条抢层级路径，只在真实隐藏或丢失 topmost 时恢复。位置、尺寸、拖动和去重提交逻辑保留。
- 狼蛛根因：旧适配只发 `13 05` 握手、未发 `13 4A` 查询；只接受固定首地址 `13 0A` 且字段解释错误；形状探测成功后又查询一次，第二次失败会丢掉第一次有效读数。
- 依据：`open24g-batmon/configs/devices/aula-f87.json` 的 F87 实机配置（`3554:FA09`）。流程为被动听 200ms → `13 05 01…19` → 等 50ms → `13 4A 01…5E`；回包优先找 `13 4A`、再找 `0A`，相对锚点 `[5]` 为电量，`[6]&0x10` 为充电位，2..100 有效。
- 修复：`providers.cpp` 实现完整流程、读写分句柄、严格输出长度、`WriteFile` 无应答后回退 `HidD_SetOutputReport`，每轮只读取一次；候选集合同时检查 IN/OUT。无应答显示「暂未读取」，历史值仍由通用 `MergeReading` 最多沿用 15 分钟并标 stale，不伪造新值。
- `decode.h` 更新协议纯函数声明，`selftest.cpp` 增加握手/查询校验、两种锚点、前导 report ID、充电位、旧 13 0A 布局兼容、0/1 占位和截断包用例；`docs/technical-notes.md` 修正旧协议记录。
- 验证：独立构建 `app/build/yudian.fixed.exe`（GUI 子系统），自检 95/95；`-Wall -Wextra -fsyntax-only` 通过，仅原有 pragma / FARPROC 转换警告；本机 `--list` 罗技 G304 90%、G913 TKL 98% 正常。本机未连接狼蛛，目标键盘和任务栏点击场景仍需人工复核。
