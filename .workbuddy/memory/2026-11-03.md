## 修：双击桌面 Token 面板.cmd 起不来（根因是 PATH 里的 0 字节 python 占位符）

- 现象：双击黑窗弹「内存资源不足，无法处理此命令。」；用户手动跑 `python --version`
  **一行输出都没有**，`python server.py --open` 也瞬间静默返回。
- 根因：用户 PowerShell 里 `python` 解析到
  `%LOCALAPPDATA%\Microsoft\WindowsApps\python.exe` —— **0 字节的应用执行别名占位符**；
  `pythonw` 则完全找不到。真实解释器在
  `%USERPROFILE%\.workbuddy\binaries\python\versions\3.13.12\`，**不在用户 PATH 上**。
- 我的误判：之前用智能体环境的 PATH 验证（那里 WorkBuddy Python 排第一）就以为没问题，
  实际上是两套环境。**教训：验证"用户双击能否成功"必须用用户的 PATH，不能拿 agent 的。**
- 修法：重写 `start-panel.bat` 的解释器查找——① 优先 WorkBuddy 自带 `versions\*\pythonw.exe`；
  ② 退到 PATH 上的 `pythonw`，但**用 `%%~zj GTR 0` 拒绝 0 字节占位符**；③ 常见安装目录兜底；
  ④ 全找不到时打印搜索过的位置并 `pause`。选中的解释器同时写入 `%TEMP%\tp-launch.log`。
- 验证：把 `start` 行换成 `echo RESOLVED=%PYW%` 的副本跑出
  `RESOLVED=C:\Users\10424\.workbuddy\binaries\python\versions\3.13.12\pythonw.exe`；
  再用该解释器实拉服务，healthz 返回 ok:true（pid 24528），随后 stop-panel.bat 干净停止。
- 桌面启动器保留诊断版（写 `%TEMP%\tp-launch.log`、记录 `errorlevel`、失败时 `pause`），
  便于下次直接定位。
- 注意：`%errorlevel%` 写在 `( )` 块里会在解析期展开拿到旧值，必须用 `goto :label` 跳出去再读。
- 另：本机 `cmd /c` 从 bash 调用偶被安全策略拦（"Invoking PowerShell from Bash"），
  改用 `cmd //c "C:\...\脚本.cmd"`（ASCII 路径）或 Python subprocess 更稳。

## token-panel 界面修复：文字截断 / 30 天统计算错 / 图表重排

- **30 天累计是硬错误**：前端 `avg_daily_30 * 30`，把「活跃日（16 天）日均」乘了 30 个自然日，
  2.67亿 × 30 = 80亿，比历史总和 43亿还大。改为后端 `window(30)` 真实求和 + 两个日均口径
  （活跃日 2.69亿 / 自然日 1.44亿）。**教训：区间累计必须求和，任何"日均×天数"都是坑。**
- **文字截断根因**：`.cap` 是 flex 但没禁换行，"标题 + 峰值提示"挤成两行把图表顶下去；
  `.sub` 强制 `nowrap` 单行省略。改为 `.cap` nowrap + hint 靠右省略，`.sub` 两行 line-clamp。
- **图表不填满卡片**：flex 高度在 ECharts 初始化时未稳定 → 画布偏小、下方留白。
  改为 `.chart` 绝对定位（top32/bottom8），并加 `relayout()` 多次 resize（rAF + 120/400/900ms）。
- **重排**：趋势与热力图并排各占半宽（面积减半、高度保留），腾出一整行放
  「项目消耗 TOP5」（横向条形）+「会话消耗 TOP5」（列表）。压高度会把坐标轴和热力图标签压烂。
- **踩坑（重要）**：连续多张截图完全一样，误以为是布局问题——实际是 Chrome `--user-data-dir`
  路径含中文时创建失败、回退默认配置，一直命中旧缓存。**截图验证必须用纯 ASCII 的 profile 路径
  + `--incognito`**，否则看到的是旧代码。
- 另一个坑：`?static=1` 下 `--virtual-time-budget` 可用（无 SSE 不会崩），能等到布局稳定再拍。
- 顺手给静态资源加版本号 `?v=3`，避免用户浏览器按 7 天缓存看到旧界面。
- 事故：用 `s.find('/* 临时诊断')` + `s.find('\nfunction renderPie')` 切片删代码，
  但锚点在前面出现 → find 返回 -1 → `s[:start] + s[0:]` 把文件头复制了一遍。
  修复：按重复前缀长度切掉一份再删。**删除代码前必须校验锚点顺序（assert end > start）。**
