## 启动器重做：消掉"闪一下 + 驻留窗口"

- 根因：桌面 `.cmd` 里用 `start "" xxx.bat` → 先开一个控制台，start 又开第二个，
  第一个随即关闭（那一下闪），第二个留着（驻留）。`pythonw` 缺失时退回 `python` 也会再多一个窗口。
- 新架构三层：桌面 `.cmd`（ASCII）→ `start-panel.bat`（ASCII，只定位解释器）→ `tools/launch.py`（UTF-8，负责一切显示）。
  服务用 `DETACHED_PROCESS|CREATE_NO_WINDOW` 拉起，本身不占窗口；**不再使用 `start`**。
- 启动器：ASCII logo + 四阶段检查（解释器/数据源/端口/启动）+ 等待就绪点号 + 绿色方框"已启动" + 等按键。
  颜色走 ANSI，用 ctypes 打开 ENABLE_VIRTUAL_TERMINAL_PROCESSING；输出编码强制 UTF-8 + `chcp 65001`。
- **坑1**：方框宽度必须用"去 ANSI 后"的可见宽度算，否则颜色码被计入宽度、边框全歪。
- **坑2**：`√ × !` 属 East Asian Ambiguous，控制台按双宽渲染，方框内不能放，只能放纯 ASCII/中文。
- **坑3**：写 .cmd 时用 Python 字符串拼 `D://WorkBuddy` 容易被多转义成 `D://WorkBuddy//`，
  改用 Write 工具直写再由 Python 统一 CRLF，最稳。
- 验证：服务在跑 → 走"复用已有实例"分支；服务停 → 完整启动（pid 变化、healthz ok）。

## 修复"按任意键"不响应空格

- 根因：`input()` 是**按行读取**，只按空格不会返回，必须回车；文案写"按任意键"是错的。
- 修复：Windows 下用 `msvcrt.getwch()`（`pause` 内部同款机制），单键立即返回、不回显；
  非交互（管道/重定向）退回 `input()`。等待前用 `kbhit()` 排空残留按键，
  否则启动过程中按过的键会被立刻消费，窗口像是"没等就关"。
- **可复用的验证技巧**：自动化里没法按键盘，但可以
  ① 测试进程 `FreeConsole()` + `AllocConsole()`；
  ② 子进程不传 creationflags，继承这个控制台；
  ③ `CreateFileW("CONIN$")` + `WriteConsoleInputW` 注入 KEY_EVENT（空格：VK 0x20 / scan 0x39）。
  实测 `getwch()` 在 0.10 秒返回 `' '`，证实无需回车。
  （先前试的 `AttachConsole(pid)` 会因 ERROR_ACCESS_DENIED 失败，别走那条路。）

## 全页实时化：seq 版本号 + bundle 快照 + 指纹重绘

- **架构**：索引器写库 → `Store.bump()` → `Store.seq()` 变化 → SSE 只推 62 字节 `{"v":…}` →
  前端 `sync()` 拉一次 `/api/bundle?range&days&weeks` → `applyBundle` → 各 render 指纹比对后重绘。
- **为什么数据不走 SSE**：series 的 days、heatmap 的 weeks 是客户端参数，服务端预知不了，
  广播完整快照必然漏掉那两张图（这正是"只有左上角实时"的根因）。
- **seq 埋点**：不放在调用方，放在 `Store.insert_events / insert_credits / delete_events_by_path / delete_file`
  内部（漏调用也不会停更）；另外广播循环兜住"跨日"和"会话切换"两种无写入的变化。
- **缓存**：`_cached` 从 TTL 改为「版本相等 + max_age 兜底」，加 `_pending` 单飞
  （4 个并发 bundle → miss 只 +7，不是 28）。`idle_s/active/delta_60s/now_hour` 必须移出缓存，
  否则状态灯会冻在"活跃"。
- **前端**：三张 `notMerge:true` 改 `merge` + 固定 series id；`tween` 的 `_v` 改为每帧回写当前值
  （原来提前写目标值，间隔 <420ms 会跳）；`drawMini/drawSpark` 加指纹；`relayout` 去掉 4 个 setTimeout。
  热力图 `visualMap.max` 加 12% 迟滞 + 窗口锚定数据最后一天，否则整图每轮变色。
- **实测**：索引器 discover 36.2ms → 2.4ms（按目录 mtime 增量枚举，每 30 拍强制全量）；
  单拍总耗时 71ms → 4-6ms；SSE 5.47KB/1.5s → 62B/次；空转重绘归零。
- **验证手法**：`?static=1&resync=1` 反复重取，用历史区间（数据不变）两张截图逐像素比，
  只有时钟区域差 125 像素 —— 证明"重复刷新零视觉变化"。比肉眼看靠谱。
